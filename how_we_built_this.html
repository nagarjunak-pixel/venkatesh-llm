How We Built Venkatesh Bommeparthi — A 1M-Parameter LLM

A complete, from-scratch, end-to-end walkthrough of every stage.
1,031,478 params Owner: Venkatesh Bommeparthi Trained on iCloud text Runs on Mac (MPS) No pretrained weights
The Big Picture — 6-stage pipeline (+ 1 diagram step)
📁 iCloud text→ data_prep.py→ tokenizer.py→ model.py (1.03M)→ train.py→ plot_loss.py→ infer.py

An extra step renders a one-page architecture diagram. Together these show how a raw text corpus becomes a generative model.

Step-by-Step Walkthrough

1

Data Preparation

Concept — Gathering, cleaning, and splitting raw text.

Why needed — Models need structured text to learn vocabulary and character transitions.

File — data_prep.py

Key detail — Scans ~/Library/Mobile Documents/com~apple~CloudDocs/ for .txt .md .markdown .json .csv .pdf (skips files >500 KB and backup folders). Compiles into corpus.txt capped at 1 MB (this run scanned 90 files → 1,058,152 bytes). Splits 90/10: train 948,455 chars / val 105,384 chars. Stats saved to meta.json.

Run — python3 data_prep.py

2

Tokenization

Concept — Mapping text symbols to integers.

Why needed — Neural networks operate on numeric tensors, not character strings.

File — tokenizer.py

Key detail — CharacterTokenizer indexes unique characters → vocabulary of 182 tokens. Index 0 reserved for <unk>. Mapping saved to vocab.json. Char-level keeps the vocab tiny (182 vs 32,000+ for subwords), preventing the embedding layer from bloating — this is what keeps the model inside the 1M-param budget.

Run — fitted inside training: python3 train.py

3

Model Design

Concept — Defining network layers and forward-pass logic.

Why needed — The architecture decides how inputs flow through attention to predict the next token.

File — model.py (config in config.py)

Key detail — TransformerLM: a GPT-style decoder-only transformer. Config: N_EMBD=128, BLOCK_SIZE=128, N_HEAD=4, N_LAYER=5, DROPOUT=0.1. Embedding (wte) and LM head (lm_head) weights are tied to save memory.

Param math (total 1,031,478)

  • Token embeddings wte: 23,296
  • Position embeddings wpe: 16,384
  • 5 decoder blocks (CausalSelfAttention + MLP + LayerNorm): 991,360
  • Final norm ln_f: 256
  • Tied lm_head bias: 182

Run — python3 -c "import config, model; print(model.build(config).param_count)"

4

Training

Concept — Optimizing weights via backpropagation.

Why needed — Adjusts parameters to learn patterns and structure from the corpus.

File — train.py

Key detail — Runs on Apple Silicon mps (or cpu) for 1,000 steps. AdamW optimizer, LR 1e-3. Optimizes cross-entropy loss (surprise of predicted vs true next-token distribution). Every 100 steps, eval is appended to loss_log.jsonl; weights + optimizer state + metadata checkpointed to checkpoints/checkpoint.pt (resumable).

Run — python3 train.py

5

Loss Visualization

Concept — Plotting train vs validation loss curves.

Why needed — Diagnoses learning speed, convergence, and overfitting.

File — plot_loss.py

Key detail — Reads loss_log.jsonl, renders loss_curve.svg + loss_curve.html. The curve shows a classic lesson: train loss falls 2.5432 → 1.4924, but val loss hits a minimum of 1.7543 at step 200, then rises to 2.9084 — the model starts memorizing the tiny training set.

Run — python3 plot_loss.py

6

Inference

Concept — Generating text from a seed prompt.

Why needed — Assesses generation by decoding probabilities.

File — infer.py

Key detail — Loads checkpoint.pt + vocab.json, supports greedy / temperature / top-k. Output is gibberish: it forms rough word shapes, but ~1.03M params + 1 MB data can't learn syntax or meaning. That is the point of the demo.

Run — python3 infer.py --prompt "Venkatesh Bommeparthi is " --max-tokens 200 --temperature 0.8

7

Architecture Diagram

Concept — Visualizing the pipeline and model internals.

Why needed — A blueprint of the codebase + data flow.

File — architecture_diagram.py

Key detail — Renders architecture_diagram.svg + .html: scripts → artifacts → checkpoint → model's internal tensor flow (Embedding → Decoder Blocks → LM Head).

Run — python3 architecture_diagram.py

What We Learned & Limitations

  • Scale: 1.03M params on ~1 MB text has tiny capacity — learns spelling/word clusters, not sentences. Real LLMs need billions of params + trillions of tokens.
  • Overfitting: val loss rises after step 200 while train loss keeps falling. Real models avoid this with huge, diverse data.
  • Tokenization: char-level is simple and param-efficient here, but yields long sequences. Production uses subword (BPE).
